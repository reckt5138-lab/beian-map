# 数据与安全

版本：V2.1 Lite 　最后更新：2026-11-21 　**上线/改动前必读**

## 一、三层数据

| 层 | 文件 | 规模（实测） | 是否进公开站 |
|---|---|---|---|
| 原始 | `output/raw/projects_YYYY-MM-DD.json` | 18 条，接口原样 | 否 |
| 完整 | `output/data.full.json` / `output/excel/*.xlsx` | 18 条，`rows` 19×158（`rows[0]` 为表头） | 否 |
| 公开 | `data.json` / `dist/data.json` | 18 条，13 列 | 是 |

`columns` 字段是**列数（整数）**，不是表头数组；表头在 `rows[0]`。

## 二、完整 payload 结构

顶层：`updated`、`source`、`sheet`、`columns`（158）、`count`、`rows`、`projects`、`generated_at`。

`projects[i]` 35 键：`name addr owner dept area customer product classify ptype build stage amount discount desc evac customerType customerQual contact customerAddr filing expire created lastSign signCount quoteTimes quoted source lastRecord duration vertical signs fields lat lng geo`。

- `fields`：该项目 158 列键值（少数项目接口返回非字典，脱敏按 `{}` 处理）
- `signs`：签到数组（实测合计 163 条）
- `geo`：`exact` / `verified` / `manual` / `district`（估算）/ `none`；当前 18 条全为 `exact`

## 三、公开 payload 结构

顶层 11 键：`updated source sheet columns(13) count rows projects generated_at public(true) redacted(true) field_policy`。

公开 13 列：项目名称、产品类型、审批类型、项目分类、项目类型、建设类型、项目进度、项目来源、备案时间、失效时间、创建时间、是否海外项目、是否改造项目。

`projects[i]` 固定 36 键：15 键有值（`name classify ptype build stage product source vertical filing expire created lat lng geo district`），19 键恒空（`addr owner dept area customer contact customerAddr customerType customerQual amount discount desc evac lastSign lastRecord signCount quoteTimes quoted` + `signs=[]`）。

## 四、脱敏逻辑（唯一入口）

`app/security/sanitize.py` + `config/public_fields.example.json`：

1. 白名单 `projects_keep` 保留
2. `projects_blank` 里的键**显式置空**（`signs` → `[]`）
3. `fields` 只保留 `columns_keep` 13 列
4. 输出 `redacted: true`

新增字段默认「不公开」，必须显式加入白名单——避免「忘了删」。发布后 `app/map/build.py` 的 `verify()` 再查：文件过小、含 `ghp_`/`github_pat_`/密码样式、缺内置快照 → 判失败不上传。

## 五、敏感数据管理

| 级别 | 字段 | 去向 |
|---|---|---|
| A 可公开 | 项目名称/类型/分类/进度/建设类型/时间/经纬度/可信度/行政区 | 公开仓库 + Pages |
| B 仅内部 | 业务员、部门、项目编号、项目情况描述、面积明细 | 仅本机 `output/` |
| C 敏感 | 客户名、联系人、电话、客户地址、金额、报价、跟进/签到明细、备注、Token/Cookie/原始响应 | 任何公开位置都不出现 |

不确定级别的字段按 C 处理。

## 六、凭证管理

| 凭证 | 存放 | 约束 |
|---|---|---|
| 青鸾账号 | 本机 `config/credentials.json`（.gitignore）/ 云端 Secrets | 不写进 BAT、不进日志 |
| GitHub PAT | 云端 `PUSH_TOKEN`；本机环境变量 `GITHUB_TOKEN` | fine-grained，仅本仓 Contents 读写 |
| CF Token | 云端 `CLOUDFLARE_API_TOKEN` | 「编辑 Cloudflare Workers」模板 |

日志过滤器会抹掉 `ghp_`/`github_pat_`/`password=`/`cookie`；诊断报告不含凭证。

**config.json 已清理**：删除了 `login.client_secret` 与 `feishu.app_id/app_secret`，`feishu.enabled=false`。代码内默认值（`client_secret="111111"`）继续保证登录可用。

- `config/credentials.json`、`output/`、`*.xlsx` 从未被跟踪。

处置选项（需负责人批准，本版本未执行）：

3. 仅覆盖当前文件（本次已做），接受历史可追溯风险

无论哪种，建议**更换青鸾密码、吊销曾明文出现过的 GitHub PAT**。
