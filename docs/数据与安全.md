# 数据与安全

版本：V3.0　最后更新：2026-11-22　**上线/改动前必读**

## 一、三层数据

| 层 | 文件 | 规模（实测） | 是否进公开站 |
|---|---|---|---|
| 原始 | `output/raw/projects_YYYY-MM-DD.json` | 接口原样 | 否 |
| 完整 | `output/data.full.json` | 18 条，`rows` 19×158（`rows[0]` 为表头） | 否 |
| 公开 | `data.json` / `dist/data.json` | 18 条，13 列，`redacted: true` | 是 |

`columns` 是列数（整数），不是表头数组；表头在 `rows[0]`。V3.0 不再导出 Excel。

## 二、公开白名单（13 列）

表头 13 列（`rows[0]`，实测）：项目名称、产品类型、审批类型、项目分类、项目类型、建设类型、项目进度、项目来源、备案时间、失效时间、创建时间、是否海外项目、是否改造项目。

`projects[i]` 保留：`name`、`classify`、`ptype`、`build`、`stage`、`product`、`source`、`filing`、`expire`、`created`、`lat`、`lng`、`geo`、`district`（区域由地址派生）。

一律置空：`addr`、`owner`、`dept`、`area`、`customer`、`contact`、`customerAddr`、`customerType`、`customerQual`、`amount`、`discount`、`desc`、`evac`、`vertical`、`lastSign`、`signCount`、`lastRecord`、`quoteTimes`、`quoted`；`signs` 固定 `[]`，`fields` 固定 `{}`。

签到相关字段（`signCount` / `lastSign` / `signs`）当前公开版本为空，页面按「0 次 / —」显示；白名单定义在 `config/public_fields.example.json`。

## 三、脱敏与校验链

```
完整矩阵 → map_payload（解析、坐标补全） → security.sanitize（白名单 + 置空）
        → data.validate（空集、骤降、重复名、日期、分页完整性）
        → data.export_json（原子写 data.json） → map.build（模板拷贝 + verify）
        → dist/
```

`verify()` 拦截：`ghp_` / `cli_` 凭证前缀、明文密码、旧数据源地址（raw.githubusercontent、jsDelivr 业务数据接口、飞书地址/spreadsheet_token）、`window.EMBEDDED` 内置快照；页面 < 20 KB 也判失败。

## 四、凭证

| 凭证 | 存放位置 | 说明 |
|---|---|---|
| 青鸾账号密码 | `config/credentials.json`（不进 Git）/ Actions Secrets | 只用于登录 |
| GitHub Token | `config/deploy.json` 或环境变量 | 用完即弃，权限只需 repo + workflow |
| Cloudflare Token | 环境变量或 `deploy.json` | 可选，备用站 |

- 代码默认配置里不含任何明文密码或 App Secret；抓取端保留的 `login.client_secret` 是青鸾网页登录接口的固定公开参数（浏览器 JS 里可见），不是用户凭证，已在代码注释里标明
- 日志有 SecretFilter，过滤 `ghp_`、`github_pat_`、`password=`、`cookie`
- 提交前扫描：`credentials.json`、`deploy.json`、`output/` 不进 Git

## 五、Git 历史注意事项

历史提交中曾出现过的类型（具体值不再记录）：登录 `client_secret` 默认值、飞书 `app_id` 与 `spreadsheet_token`、以及一次 158 列完整 `data.json`。

处置建议（需人工决定，脚本不擅自执行）：

1. **最省事**：仓库转 Private，或只保留当前干净文件（历史仍在，风险自担）。
2. **彻底**：用 `git filter-repo` 重写历史后强推，并同步轮换青鸾密码、飞书 App Secret、GitHub Token。
3. **无论哪种**：对话/文档里出现过的 Token 都应视为已泄露，建议吊销重建。

## 六、红线

- 不得把 158 列完整数据上传到公开仓库或 Pages
- 不得提交 `credentials.json`、`deploy.json`
- 不得在页面里写死飞书地址、spreadsheet_token、raw/jsDelivr 数据接口
- 不得在页面加载失败时伪造 0 条数据
- 不得未经确认重写 Git 历史或强推
