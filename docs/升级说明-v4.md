# V4.0 升级说明：项目分类导航 + 合同/回款/发货

本版本在 V3.0 纯备案地图基础上，新增「备案项目 / 成交项目」双分类视图，
并在项目明细「项目来源」下方增加合同信息与合同详情（产品明细、金额合计）。

- 版本基线：V3.0（`beian-map-v3`，保持不动）
- 工作副本：`beian-map-v4`
- 分支：`feat/project-type-contract-finance`（未提交、未推送）
- 数据安全原则：合同与财务数据不进入公开 `data.json`、不进入 `dist`、不进入 Pages

---

## 1. 功能范围

### 1.1 顶部项目分类导航

- 地图主体上方新增两个横向按钮：`备案项目`、`成交项目`，默认选中备案项目。
- 切换时不重载页面、不重建地图实例，只做三件事：移除旧点位、按新分类建点位、重算列表/统计/筛选数量。
- 同步更新的范围：地图点位、项目列表、项目总数、北京/异地统计、失效分布筛选数量、搜索与筛选结果、底部“项目列表”计数。
- 当前分类无数据时，地图中央显示空状态提示，列表显示“当前分类暂无项目”。
- 无法确认类型的项目不会进入任何分类，Tab 右侧显示“另有 N 个项目类型无法确认，未归入任何分类”。

### 1.2 项目明细合同信息

- 位置：项目信息区块（最后一项为“项目来源”）之后的独立区块“合同信息”。
- 每份合同逐条展示：合同编号（可点击）、合同金额、未回金额、回款率（数字 + 进度条）。
- 一个项目可关联多份合同，逐条展示。
- 状态区分（不允许一律显示为空）：
  - `暂无关联合同`：确实没有合同编号；
  - `无权限查看合同与回款信息`：受控接口返回 401/403；
  - `合同接口异常：…`：网络失败、HTTP 5xx、JSON 非法，并给出“重新加载合同信息”按钮；
  - `合同财务数据尚未接入受控接口`：`./contracts.json` 不存在（404）；
  - `已关联合同编号，但合同金额与回款数据尚未由财务系统提供`：有编号无财务记录。

### 1.3 合同详情

- 点击合同编号，在原有抽屉内打开合同详情（不跳转页面）。
- 顶部：合同编号、合同金额、已回款金额、未回金额、回款率（含进度条）、产品数量。
- 中部：异常提示（作废/冲销/退款未计入、回款超合同、金额缺失等）。
- 下部：产品明细表，列为 序号 / 产品名称 / 合同金额 / 发货金额，表底“合计”行加粗并统计两列合计。
- 无产品时显示“暂无产品明细”；单项金额缺失时显示“暂无数据”，不显示 0。
- “‹ 返回项目详情”回到原项目明细，保留地图位置、当前分类 Tab、搜索词与筛选条件。
- 表格容器横向滚动，移动端不产生整页横向溢出。

## 2. 数据来源映射

| 前端字段 | 来源 | 说明 |
| --- | --- | --- |
| 项目分类 `pkind` | `app/project_type.py` 依据「项目分类」`classify`（回退 `status` / `projectStatus`）判定 | 仅匹配 `备案项目` / `成交`（兼容 Tab 文案 `成交项目`），其余为 `unknown`；绝不按项目名称猜测 |
| 合同编号 | 列表接口字段 `contractNo`（详情回填 `contractNoText`） | 实测 12 个成交项目共 23 份合同，支持逗号分隔的多合同，编号内连字符与斜杠保留 |
| 合同金额 | 财务导出 JSON 的 `contracts[].contractAmount` | 后端 `Decimal` 解析，两位小数字符串；缺失为 `null` |
| 已回款金额 | 财务导出 `contracts[].receipts[]`（含 `amount`、`status`、`date`） | 多笔累计；作废/冲销/退款/负数为无效记录 |
| 未回金额 | 合同金额 − 已回款金额 | 负数保留并产生异常提示，不静默修正 |
| 回款率 | 已回款 ÷ 合同金额 × 100 | 合同金额为 0 或为空时不计算，显示“暂无数据” |
| 产品名称/合同金额 | 财务导出 `contracts[].products[].name` / `.amount` | 产品金额缺失显示“暂无数据” |
| 发货金额 | 财务导出 `products[].deliveries[].amount` 累计，回退 `shippedAmount` | 多次发货累计；作废发货不计入；缺失不补 0 |

### 2.1 项目分类接口实测（2026-11-25）

网页顶部 Tab 与接口 `projectTabType` 对应、以及 `projectStatus` 的真实取值如下：

| Tab 文案 | projectTabType | 接口 projectStatus | 条数 |
| --- | --- | --- | --- |
| 成交项目 | 1 | 成交 | 12 |
| 丢失项目 | 2 | 丢失 | 2 |
| 失效项目 | 3 | 失效 | 3 |
| 非备案人报价项目 | 4 | 非备案人报价项目 | 1 |
| 备案项目 | 5 | 备案项目 | 21 |
| 全部项目 | 100 | — | 39 |

抓取仍使用 `tab_types=[100]` 一次取全部，再按 `projectStatus` 过滤为「备案项目 + 成交」，本次结果 39 条 → 保留 33 条（21 备案 + 12 成交），剔除 丢失 2 / 失效 3 / 非备案人报价 1。

**关键点**：接口值是「成交」而不是「成交项目」，只按 Tab 文案过滤会把 12 条成交项目全部丢掉；`filter_rows_by_status` 已做别名展开（`成交项目 → 成交`）。

### 2.2 现有接口边界（重要）

当前 V3/V4 抓取链路（`app/crawler.py` + `config/api`）只覆盖：登录、用户信息、项目列表/详情、跟进记录、客户信息、导出。
**没有任何接口返回合同金额、回款记录、产品明细与发货记录。**
因此本版本采取“结构先行 + 受控数据源”方案：

1. 合同编号：来自真实列表字段，已可用；
2. 合同金额/回款/产品/发货：由财务系统导出受控 JSON（`--finance`），后端计算后生成 `private/contracts.json`；
3. 前端只请求同源 `./contracts.json`，浏览器不持任何账号、Token、Cookie。

### 2.3 `contracts.json` 契约

```json
{
  "updated": "2026-11-25",
  "source": "受控财务数据（非公开）",
  "restricted": true,
  "note": "本文件含合同与财务信息，禁止放入 dist、Pages 或公开仓库。",
  "projects": {
    "项目名称": {
      "status": "ok | no_contract | no_finance_record | source_not_configured",
      "pkind": "filing | deal | unknown",
      "contracts": [
        {
          "contractNo": "HT-...",
          "contractAmount": "100,000.00",
          "receivedAmount": "70,000.00",
          "unreceivedAmount": "30,000.00",
          "collectionRate": "70.00",
          "products": [
            {"seq": 1, "name": "产品", "contractAmount": "60,000.00", "shippedAmount": "50,000.00"}
          ],
          "totalContractAmount": "100,000.00",
          "totalShippedAmount": "90,000.00",
          "productsIncomplete": false,
          "anomalies": [{"code": "...", "message": "..."}]
        }
      ],
      "summary": {"contractAmount": "...", "receivedAmount": "...", "unreceivedAmount": "...", "collectionRate": "..."}
    }
  }
}
```

金额统一为千分位两位小数字符串；未知一律 `null`，不以 0 代替。

## 3. 金额与回款口径

- 全部使用 `decimal.Decimal`，禁止浮点运算；输出 `ROUND_HALF_UP` 两位小数。
- 有效回款：状态含 `作废/冲销/退款/红冲/撤销/无效/void/reverse/refund/cancel` 的记录不计入；金额为负视为冲销不计入。
- 无回款记录：已回款按 0 统计，并写入 `receipts_missing` 异常（提示“暂按 0 元统计”）。
- 合同金额 0：回款率不计算，写 `contract_amount_zero` 异常。
- 合同金额空：金额、未回金额、回款率均为 `null`。
- 回款超过合同：未回金额为负、保留原值，写 `received_exceeds_contract` 异常。
- 产品多次发货累计；作废发货跳过；无发货记录写 `delivery_missing`，发货金额保持 `null`。
- 产品部分金额缺失时，合计只累计已有值，并标记 `productsIncomplete`。

> 默认口径为“作废/退款不计入回款”。若财务系统口径不同，必须由后端修改 `app/finance.py` 的 `VOID_KEYWORDS` 规则，不允许前端改数。

## 6. 未解决与待确认

1. **财务接口缺失**：合同金额、回款、产品、发货仍无上游接口，需要业务方提供导出或由后端新增受控查询；在此之前合同区显示“尚未接入/暂无财务记录”，不显示任何金额。
2. **成交项目已接通**：12 个成交项目、23 份真实合同编号已抓到；受控数据中这 12 个项目为 `source_not_configured`，前端只显示真实合同编号并提示“财务数据未提供”。
3. **作废/退款口径**：当前默认排除，需财务确认；如是“部分冲销”等复杂场景，需扩展规则。
4. **权限模型**：受控接口鉴权尚未实现，当前依赖部署层（内网/网关鉴权）保护；公开站无该文件时前端明确提示未接入。
5. **Git**：本机无 git 可执行文件，仅通过 `.git` 引用切到 `feat/project-type-contract-finance`，未提交、未推送。

## 7. 人工验收步骤

1. 打开地图，确认默认选中“备案项目”，顶部数字与列表、点位一致。
2. 点击“成交项目”，确认备案点位全部消失、列表清空、显示空状态；再切回备案，点位恢复。
3. 搜索关键词、切换“7 天内/8–14 天”等筛选，确认数量与列表随分类变化。
4. 打开任一项目明细，滚动到“项目来源”下方，确认出现“合同信息”。
5. 无合同项目显示“暂无关联合同”；临时把 `contracts.json` 返回 403，确认提示“无权限”；删除文件确认提示“尚未接入”。
6. 切到“成交项目”，确认 12 条真实成交项目；打开任一项目，合同区显示真实合同编号（多合同逐条），金额类字段显示“暂无数据”并提示财务数据未提供。
7. 在合同详情点“返回项目详情”，确认地图位置、Tab、搜索词、筛选条件均保留。
8. 缩窄窗口到手机宽度，确认 Tab 不遮挡地图、明细与表格不横向溢出整页。
