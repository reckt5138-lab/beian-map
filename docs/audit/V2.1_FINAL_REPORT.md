版本：V2.1 　生成时间：2026-11-21 　范围：`C:\Users\Administrator\Desktop\新建文件夹 (3)\jbufa_project_export_v2`（原工程 `jbufa_project_export` 未改动）

## 一、项目原始状态

- V2 单层结构：`app/` 下十几个大文件并列，无 `core/data/map/security` 分层，无测试。
- `data.json` 为 **158 列完整数据**，随公开仓库与 GitHub Pages 发布约 1 小时（含客户名/电话/金额）——**严重安全问题**。
- 本机 `git push` 因 TLS 抖动（`schannel: server closed abruptly`）不可用，提交依赖手工重试。
- 无数据校验、无原子写：抓取失败会直接覆盖好数据。
- 入口混乱：`测试运行.bat` / `一键部署.bat` / `定时任务启动.bat` 职责重叠，无中文提示分级。

## 二、修改后的架构

```
app/main.py（7 命令 CLI）
 ├ app/core      paths / config / logging_config / exceptions
 ├ app/data      atomic / validate / export_json
 ├ app/map       build（渲染 + verify）
 ├ app/security  sanitize（白名单脱敏）
 └ app/crawler.py、map_payload.py（旧核心，原地保留）
```

发布链：`crawl → validate → sanitize → build → verify → Contents API 提交 → Pages（CF 可选）`，任一步失败即不发布。

## 六、修复的问题

1. 公开完整数据的严重泄露 → 白名单脱敏 + 自检（已覆盖线上）。
2. 无数据校验/覆盖风险 → `validate` + 原子写 + 上一版快照 + 60% 下降阻断。
3. `git push` 不可用 → Contents API 提交。
4. 无测试 → 35 项，全绿。
5. 配置散落无优先级 → `app/core/config.py`（env > credentials > config > 默认）+ 缺失中文提示。
6. 日志可能含凭证 → SecretFilter。
7. 包 `__init__` 与子模块同名遮蔽、`BASE_DIR` 少一层、`sanitize` 丢 `projects_blank`、字段列表型兜底 → 全部修复（测试排障中发现）。
8. `cmd_selftest` 调用未导入的 `validate`、把临时页面写进 `dist` → 已修为 `validate_payload` + 写 `output/`。
