# 部署清单（v2 · 无飞书 · 全免费）

> 目录：`jbufa_project_export_v2`
> 目标：**云端每天定时抓数（电脑关机照跑）→ 出 `data.json` + Excel → 免费网页随时访问**。不写飞书，不需要服务器。

---

## 方式 A：一键部署（推荐，约 2 分钟）

双击 `一键部署.bat`，按提示填三样：**GitHub 用户名 / 仓库名 / Token**。脚本会自己完成：

1. 校验 Token（顺便确认身份）
2. 创建仓库（默认公开；要私有加 `--private`）
3. `git init` → 提交 → 推送（token 只用一次，不会留在 `.git/config`）
4. 从本机 `config\credentials.json` 读取青鸾账号，加密后写入 Actions Secrets（只有 `JUFA_USERNAME`、`JUFA_PASSWORD` 两项）
5. 把仓库地址写进 `config\config.json` 的 `publish`，重建 `index.html` 并推送
6. 打开 Actions 的读写权限，并立刻触发第一次云端运行

Token 怎么拿：GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)** → Generate new token，勾 **`repo`** 和 **`workflow`**（推 `.github/workflows` 必须有 workflow 权限）。

常用参数：

```powershell
python scripts\deploy_github.py --dry-run     # 只打印要做什么，不动手
python scripts\deploy_github.py --private      # 建私有仓库（本地页面就读不到 Raw 了）
python scripts\deploy_github.py --owner me --repo beian-map --token ghp_xxx
python scripts\deploy_github.py --skip-secrets --no-trigger

REM 顺带把免费网页（Cloudflare Pages）也配上
python scripts\deploy_github.py --owner me --repo beian-map --token ghp_xxx ^
  --cf-token CF_TOKEN --cf-account ACCOUNT_ID --cf-project beian-map
```

也可以把参数直接放进 `config\deploy.json`（别提交它，已在 `.gitignore` 里）：

```json
{
  "owner": "你的用户名", "repo": "beian-map", "token": "ghp_xxx", "private": false,
  "cf_token": "", "cf_account": "", "cf_project": "beian-map"
}
```

跑完看 <https://github.com/你的用户名/仓库名/actions>，第一次运行成功后仓库根目录会出现 `data.json` 的提交。

## 方式 B：手动部署

Git 已装但不在 PATH，先临时加进去（只对当前窗口有效）：

```powershell
$env:Path += ';C:\Program Files\Git\bin'
git --version
python -m pip install -r app\requirements.txt
```

## 1. 建仓库并推上去

1. GitHub → New repository → 名字如 `beian-map` → **Public**（本地页面才能直接读 Raw/jsDelivr，且 Pages 免费用）→ 不要勾 README/.gitignore → Create。
2. 在该目录里执行（换成实际值）：

```powershell
cd 'C:\Users\Administrator\Desktop\新建文件夹 (3)\jbufa_project_export_v2'
git init -b main
git add .
git status --short        # 确认没有 config/credentials.json、没有 output/
git commit -m "init: 备案项目地图 v2（Actions + data.json + index.html，无飞书）"
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main
```

`.gitignore` 已排除：`config/credentials.json`、`config/deploy.json`、`output/`、`dist/`、`备案项目地图.html`、`projects.json`、`__pycache__`。进仓库的是代码 + `index.html` + `data.json`。

## 2. 配 Secrets（只有两项）

仓库 → Settings → Secrets and variables → Actions → New repository secret：

| 名称 | 值 | 必填 |
| --- | --- | --- |
| `JUFA_USERNAME` | 青鸾账号 | ✅ |
| `JUFA_PASSWORD` | 青鸾密码 | ✅ |
| `CLOUDFLARE_API_TOKEN` | 见第 6 步 | 可选 |
| `CLOUDFLARE_ACCOUNT_ID` | 见第 6 步 | 可选 |
| `CLOUDFLARE_PROJECT_NAME` | 见第 6 步 | 可选 |

> **不再需要** `FEISHU_APP_ID` / `FEISHU_APP_SECRET` —— workflow 里 crawler 已固定 `--no-feishu`。

顺便看一下 Settings → Actions → General → Workflow permissions，选 **Read and write permissions**（workflow 已声明 `contents: write`，这里再放宽一层更保险）。

## 3. 把仓库地址写进页面

编辑 `config\config.json` 的 `publish`：

```json
"publish": { "github_owner": "你的用户名", "github_repo": "仓库名", "branch": "main" }
```

然后重建页面并推送：

```powershell
python app\build_map_html.py --from-json data.json --out index.html
git add config/config.json index.html
git commit -m "config: 指向云端仓库"
git push
```

（Actions 里不用管这步，它自动用 `GITHUB_REPOSITORY`，发布到 Pages 时页面直接读同目录 `data.json`。）

## 4. 手动跑一次，验证闭环

仓库 → Actions → 「备案项目地图每日更新」→ Run workflow → 等 1–3 分钟。成功标志：

- 日志出现 `抓取完成` + `网页数据：data.json`
- 出现「data.json 已更新 / 无变化」日志
- 仓库根目录 `data.json` 的提交时间就是刚才
- 该次运行的 Artifacts 里能下载 `备案项目XXXX-XX-XX.xlsx`（保留 30 天）

失败看日志末尾：登录失败多半是 Secrets 账号密码错；`--json-out` 报错看列数（原始 JSON 模式列数会比 Excel 多，正式流程不用它）。

## 5. 日常使用

| 场景 | 做法 |
| --- | --- |
| 本地验数据对不对 | 双击 `测试运行.bat`，跑完自动打开当天 Excel |
| 电脑看网页 | 双击 `打开地图.bat`（起本地 HTTP + 打开 `index.html`，数据取云端） |
| 手机 / 任意设备 | `https://你的用户名.github.io/仓库名/`（已自动启用，免费） |
| 临时换仓库试 | `index.html?repo=用户名/仓库名` |
| 断网 | 页面自动退回内置快照，照旧可看 |

本地**不需要**常驻调度器：定时已经交给云端，电脑关机也照跑。（`定时任务启动.bat` 是旧飞书路线遗留，可不用。）

## 6. 网页发布（两条路，都免费）

**默认已生效：GitHub Pages（零额外账号）**

部署脚本会自动启用 Pages（`build_type=workflow`），workflow 里两个 job 跑完就有固定链接：

```
https://你的用户名.github.io/仓库名/
```

改动页面样式后不用管，下次 Actions 会自动重新发布。

**可选加速：Cloudflare Pages（国内访问更稳）**

额度足够：每月 500 次构建、带宽与请求不限。

1. <https://dash.cloudflare.com> 免费注册 → Workers & Pages → Create → Pages → **Direct Upload** → 项目名 `beian-map`。
2. 头像 → My Profile → **API Tokens** → Create Token → 权限 **Cloudflare Pages: Edit** → 复制。
3. **Account ID** 在控制台右侧栏（或 Workers & Pages 概览页）。
4. 三个值填进仓库 Secrets（`CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_PROJECT_NAME`）。
5. 再跑一次 workflow，日志出现部署记录后，链接就是 `https://beian-map.pages.dev/`。

`dist/` 里同时发 `index.html` 和 `data.json`，两条路的页面都读同源数据，永远是最新一次抓取结果。

## 排错速查

| 现象 | 原因 / 处理 |
| --- | --- |
| workflow 报 403 / `Permission denied` | 第 2 步的 Workflow permissions 没放开 |
| 页面顶部写「未配置云端仓库」 | `index.html` 是用旧模板构建的（`window.CLOUD` 注入顺序 bug 已修），跑 `python app\build_map_html.py --from-json data.json --out index.html` 重建 |
| 重跑一键部署时 git push 一直超时 | 脚本会自动改用 GitHub API 逐文件推送（跳过 data.json / index.html，这两个由云端生成），日志里能看到「API 推送：成功 N 个」 |
| `data.json` 一直不更新 | 青鸾账号密码错，或站点改版导致登录失败（看日志里 `code=001`） |
| 页面状态栏写「内置快照」 | 没配 `publish` 且没重建，或仓库是 Private，或 `file://` 直开（改用 `打开地图.bat`） |
| 页面写「云端CDN」但数据旧 | jsDelivr 缓存，workflow 已加 purge，等几分钟或改用 Pages 链接 |
| Pages 部署步骤报错 | 三个 `CLOUDFLARE_*` 少填一个，或 Token 权限不是 Pages:Edit |
| 手机打不开 `电脑IP:8080` | 防火墙没放行；用 `scripts\open_firewall.bat`（管理员） |
